# ADR-0002: 祝日カレンダーを内蔵しない

- 状態: 採用
- 日付: 2026-09-08

## 背景

日本の業務では「営業日だけ動く」処理が多い。契約更新の通知、入金の消し込み、来店予約の確認——いずれも土日祝には動かさない。

これを扱わないと、**休業日のたびに「止まった」と通知が飛ぶ**。担当者は数週間で通知を無視するようになる。**無視される通知は、無いのと同じである。** むしろ「見張っている」という誤った安心を与える分だけ有害になる。

では祝日をどう判定するか。素直な案は、祝日の一覧をライブラリに内蔵することである。

しかし日本の祝日には次の性質がある。

- **法律で変わる。** 山の日の新設（2016）、天皇誕生日の移動（2020）、五輪に伴う祝日移動（2020・2021）
- **前年に閣議決定される。** 来年の祝日は、今年になるまで確定しない
- **企業ごとに休業日が違う。** 年末年始、夏季休業、創立記念日。不動産会社は水曜定休が多い

内蔵すると、**ライブラリを更新しない限り、来年から静かに間違い始める。** しかも間違いに気づくのは「祝日に通知が飛んだ」ときであり、そのときには信頼を失っている。

## 決定

**休業日の一覧は、利用者が渡す。** ライブラリは持たない。

```ts
const calendar = defineCalendar({
  weeklyHolidays: ["saturday", "sunday", "wednesday"],  // 水曜定休
  holidays: ["2026-01-01", "2026-01-12", "2026-02-11"], // 祝日・特別休業日
});
```

週の休みと、日付指定の休みを分けて受け取る。日付指定には祝日も年末年始も創立記念日も入れられる。**ライブラリ側は「休業日かどうか」を判定するだけで、何が休業日かは知らない。**

## 結果

### 得るもの

- **陳腐化しない。** 法律が変わっても、ライブラリの更新は要らない
- 企業ごとの休業日（水曜定休、夏季休業）をそのまま扱える
- 判定が決定論的になる。渡した一覧だけで結果が決まる
- 実行時依存がゼロのままでいられる（祝日データを持たないため）

### 失うもの

- **利用者が一覧を用意する手間がかかる。** 何も渡さなければ、土日だけが休みとして扱われる
- 一覧の更新を忘れると、その年の祝日に誤検知する

後者への備えとして、**日付指定の休業日が今日より未来に1件も無い場合、警告を出す**。一覧が古くなっていることに、誤検知が起きる前に気づける。

## 却下した案

| 案 | 却下理由 |
|---|---|
| 祝日の一覧を内蔵する | 法改正で静かに間違い始める。企業ごとの休業日も扱えない |
| 祝日APIを実行時に呼ぶ | 実行時依存とネットワーク依存が増える。**見張り番が外部に依存すると、外部が落ちたときに見張れない** |
| 祝日を計算で求める（春分の日など） | 移動祝日や振替休日の規則が複雑で、しかも法改正で変わる。計算しても正しさを保証できない |
