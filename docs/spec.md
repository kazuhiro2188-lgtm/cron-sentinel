# cron-sentinel 仕様書

> 何を作るか・なぜ作るかを定める。技術スタックはここには書かない（→ `docs/adr/`）。

## 1. 解決する問題

定時に動くはずの処理が、**動かなかった**とき、それに気づく手段が無い。

```
失敗はログに残る。しかし、実行されなかったことはログに残らない。
```

エラー監視の道具は数多くあるが、それらは**何かが起きたとき**に反応する。**何も起きなかったとき**には、何も起きない。

### 1.1 賃貸管理で実際に起きること

| 止まるもの | 気づけない理由 | 影響 |
|---|---|---|
| ポータルサイトへの物件情報の更新 | **掲載は昨日のまま残っている。画面上は正常に見える** | 成約済み物件が載り続ける（おとり広告のリスク）／新規物件の反響が来ない |
| 契約更新の3ヶ月前通知 | 通知が来ないのは「対象が無い日」と区別がつかない | 更新手続きが漏れ、法定更新になって更新料が取れない |
| 賃料入金の消し込み | 月末にまとめて確認するまで分からない | 督促の遅れ、オーナー報告の遅れ |

気づくのが「なんか今月、反響少なくない？」という会話になる。**そのときには数日経っている。**

## 2. 何を作るか

**動いたときに報告させ、報告が来ないことを検知する。**

動かなかったものは自分では何も言えない。だから「動いた」という報告の**不在**を見る。

### 2.1 2つの役割

| 役割 | やること | どこで動くか |
|---|---|---|
| **報告する側** | 処理が終わったら「動いた」と記録する | 監視対象の処理の中 |
| **見張る側** | 予定時刻を過ぎても報告が無いジョブを見つける | **監視対象とは別の場所**（ADR-0001） |

### 2.2 判定の種類

| 判定 | 意味 |
|---|---|
| `ok` | 直近の予定時刻ぶんの報告が来ている |
| `late` | 予定時刻を過ぎたが、まだ猶予の内側 |
| `missing` | **猶予を過ぎても報告が無い。これが本題** |
| `failed` | 報告は来たが、失敗したと報告された |
| `never_ran` | 一度も報告が無い。設置し忘れの可能性がある |
| `not_due` | 今日は予定が無い（営業日でない、など） |

`never_ran` を `missing` と分けるのは、**原因がまったく違う**ため。前者は「仕掛けを入れ忘れた」、後者は「動いていたものが止まった」。

### 2.3 猶予（grace）

予定時刻ちょうどに報告が来ることはない。処理には時間がかかる。だからジョブごとに猶予を設ける。

```
予定 06:00 ／ 猶予 30分
  06:20 に報告 → ok
  06:40 時点で報告なし → missing
```

猶予を長くすれば誤検知は減るが、気づくのが遅くなる。**処理の所要時間 + 少しの余裕**が目安になる。

### 2.4 営業日を扱う（日本の業務の前提）

「営業日だけ動くジョブ」を土日祝に「止まった」と通知すると、担当者はすぐ通知を無視するようになる。**無視される通知は、無いのと同じである。**

ジョブごとに `onlyBusinessDays` を指定できるようにする。営業日の判定には、**利用者が渡した休業日の一覧**を使う（ADR-0002）。

### 2.5 同じ欠測で鳴り続けない

止まっている間ずっと通知すると、担当者は通知を切る。

**1つの予定時刻につき、通知は1回だけ**にする。06:00 の実行が欠測したら、その日の 06:00 分について1回だけ知らせる。翌日また欠測すれば、それは別の予定時刻なので改めて知らせる。

### 2.6 見張り番自身が止まったら

**この問題は原理的に解決しない。** 見張り番を見張る仕組みを作れば、今度はそれを見張る必要が出る。無限に続く。

できるのは、**止まりにくい場所に置く**ことだけである。

| 置き場所 | 止まりにくさ |
|---|---|
| 監視対象と同じサーバー | ✗ サーバーごと落ちたら見張りも死ぬ |
| 別のサーバー | △ そのサーバーも落ちうる |
| **GitHub Actions などの外部サービス** | ○ 自社の障害とは独立している |

**この限界は隠さず文書に書く。** 「完全に監視できます」と言うほうが危険である。

## 3. やらないこと

| やらないこと | 理由 |
|---|---|
| 通知の送信（メール・Slack等） | 判定結果を返すだけにする。送信手段を抱えると、送信先の都合で本体を変えることになる |
| ジョブの実行 | これは見張り番であって、実行基盤ではない（実行は agent-kit の担当） |
| 祝日カレンダーの内蔵 | 法律で変わる。内蔵すると必ず陳腐化する（ADR-0002） |
| cron 式（`0 6 * * *`）の完全対応 | 読みにくく、誤りに気づきにくい。日本語で読める形の指定にする |

## 4. 完成の定義

- [ ] 定時ジョブの予定を宣言できる（毎日◯時／N分ごと／毎週◯曜）
- [ ] 処理側から「動いた」と報告できる
- [ ] 予定時刻を過ぎても報告が無いジョブを検出できる
- [ ] 猶予をジョブごとに設定できる
- [ ] 営業日だけ動くジョブを、休業日に誤検知しない
- [ ] 一度も動いていないジョブを、止まったジョブと区別できる
- [ ] 同じ欠測について繰り返し通知しない
- [ ] 判定は同じ入力なら同じ結果になる（時刻を外から渡せる）
- [ ] 実行時依存がゼロである
- [ ] CI でテスト・型チェック・ビルドが通っている
